Artifact Flow

How content moves through the CRLD pipeline

Pipeline Artifact Flow Diagram
LO_BRIEF → RESEARCH_BRIEF → IDEAL_BLUEPRINT → BUILD_SPEC → MODULE_PPTX ↕ (living) REVIEW_REPORT → ANNOTATED_PPTX ↓ BUILD_LOG → FINAL_MODULE

Key Concept: Living Artifacts

The IDEAL_BLUEPRINT is a "living artifact" (Directive 22). It is initially created by research agents (RA-*) in P1, then updated by review agents (Rev-*) during P2 review. This eliminates re-derivation round-trips and keeps design documents synchronized with review findings.

Generated By RA-* team (P1 Phase 1f)
Consumed By P2, P3, P5, P6

Purpose Pedagogical research, representation guidance, misconceptions, evidence
IDEAL_BLUEPRINT
Generated By RA-* team (P1 Phase 4c)
Updated By Rev-* team post-review (P2)
Consumed By P2, P3, P5, P6, P9, P10
Mutability Living Artifact (D22)
Purpose Slide-by-slide pedagogical design, trope alignment, CPA progression
Ownership Model: RA-* team creates the artifact. Each Rev-* agent owns specific categories (e.g., Rev-Ped owns pedagogical sections). After review, Rev-* agents update their sections with findings and recommendations.
KNOWLEDGE_LEDGER
Generated By RA-Ped (P1 Phase 0)
Consumed By All downstream pipelines (P2, P3, P5, P6)
Updated By Bld-* agents during module/applet build
Purpose Cumulative student knowledge state, vocabulary tracking, prerequisite continuity
Review Artifacts
REVIEW_REPORT
Generated By Rev-* team (P2 Phase 5–6, P6 Phase 5–6)
Consumed By P3 Mode C, P9 (remediation loop), P10 (reframe loop)
Format Markdown (.md) + annotated PPTX
Purpose Quality assessment, defect taxonomy, verdict (Ship-ready / Upgradeable / Remediate / Reframe)
Structure: §1 Executive summary, §2 Tier 1 gate results, §3–§10 per-category scoring (12 categories), §11 defects organized by severity, §12 recommendations, §13 verdict rationale.
ANNOTATED_PPTX
Generated By Rev-* team during P2 / P6 review
Consumed By Human reviewers, P3 Mode C builders
Format PowerPoint with reviewer comments
Purpose Visual presentation of findings, defect locations, suggested improvements
Build Artifacts
BUILD_SPEC
Generated By Build team at Phase 0 (v2.1)
Generated In P3 Phase 0 or P5 Phase 0
Source Data IDEAL_BLUEPRINT + RESEARCH_BRIEF (+ REVIEW_REPORT if Mode C)
Purpose Slide-by-slide production specification, mode-specific instructions, time budget, CPA targets
v2.1 Change: BUILD_SPEC is no longer produced by research phase. It is derived by the Build team just-in-time at Phase 0, allowing mode-specific optimization and incorporation of review findings (if Mode C).
MODULE_PPTX / APPLET_PPTX
Generated By Bld-* team (P3 / P5)
Consumed By P2 (review), human educators, production systems
Format PowerPoint (.pptx), research-informed slides with facilitator notes
Purpose Complete pedagogical content, classroom-ready instruction material
BUILD_LOG
Generated By Bld-* team (P3 / P5)
Consumed By Human reviewers, archival/audit systems
Format Markdown (.md)
Purpose Build decisions, slide construction notes, gaps logged, time tracking
System Artifacts
PIPELINE_STATE
Generated By Orchestrators
Consumed By All orchestrators (Master, Research, Review, Build)
Purpose Tracks execution state, completed phases, HOLD status, resume checkpoint
Stored In .pipeline_workspace/ directory
Usage: When a pipeline pauses (HOLD status), its PIPELINE_STATE is persisted. On resume, orchestrators load PIPELINE_STATE to recover the last completed phase and continue execution.
AGENT_OUTPUT (NEW)
Generated By Individual agents (RA-*, Rev-*, Bld-*)
Purpose Mid-pipeline checkpoint files, agent completion status, context artifacts
Stored In .pipeline_workspace/agents/ (per phase)
Lifetime Discarded after phase completion (unless errors occur)

Handoff Protocol

Cross-Team Handoff Protocol

Research → Review → Build boundaries are defined in Cross_Team_Handoff_Protocol.md. Handoffs include artifact validation gates:

Research → Review: LO_BRIEF + RESEARCH_BRIEF + IDEAL_BLUEPRINT must be present. Human gate approves research artifacts before review can begin.

Review → Build: REVIEW_REPORT verdict determined. IDEAL_BLUEPRINT may be updated by Rev-* agents. Build team derives BUILD_SPEC from IDEAL_BLUEPRINT + RESEARCH_BRIEF (+ REVIEW_REPORT if remediation).

Build → Deployment: MODULE_PPTX + BUILD_LOG produced. Human gate approves built content. Marked for deployment or routed to P9 (remediation) or P10 (reframe).
