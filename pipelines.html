Loading Mode & Checkpoint Recovery

LOADING_MODE Protocols: All orchestrators (Research, Review, Build, Master) implement LOADING_MODE on resumption. Execution state is tracked in PIPELINE_STATE artifact. If a pipeline pauses (HOLD status), it can resume from the last completed phase. Checkpoint files are stored in .pipeline_workspace/ directory.

Composite Paths in Detail
P8 Path A
Research → Build → Review (New Content)

When to use: New content, no source PPTX, full production cycle.

Step 1: Invoke P1 (Chapter Research Pipeline) ├─ Scope: full_chapter ├─ Produces: CHAPTER_BRIEF, CHAPTER_LO_SEQUENCE, │ per-module {LO_BRIEF, RESEARCH_BRIEF, IDEAL_BLUEPRINT} └─ Human Gate: Research artifacts approved? Step 2: Invoke P3 Mode A (Module Build, New Build) ├─ For each module (parallel or serial) ├─ Phase 0: BUILD_SPEC derived from IDEAL_BLUEPRINT + RESEARCH_BRIEF ├─ If module contains applets → P5 child mode invoked per applet └─ Human Gate: Built PPTX approved? Step 3: Invoke P2 (Module Review Pipeline) ├─ For each built module (parallel or serial) ├─ If module contains applets → P6 child mode invoked per applet ├─ Produces: REVIEW_REPORT.md + annotated PPTX per module └─ Human Gate: Verdict? (APPROVE / REMEDIATE / REFRAME)
P8 Path B
Research → Review → Build (Source-Informed Rebuild)

When to use: Source PPTXs exist, want pedagogical improvement grounded in research.

Step 1: Invoke P1 with source PPTXs as reference ├─ Produces: Same as Path A Step 2: Invoke P2 on source PPTXs ├─ Input: Source PPTX, RESEARCH_BRIEF, IDEAL_BLUEPRINT ├─ Produces: REVIEW_REPORT identifying improvement areas └─ Human Gate: Review accepted? Step 3: Invoke P3 Mode B or C (Source-Informed / Reviewed Rebuild) ├─ Phase 0: BUILD_SPEC derived from IDEAL_BLUEPRINT + RESEARCH_BRIEF + REVIEW_REPORT ├─ Produces: Improved Module PPTX + BUILD_LOG └─ Human Gate: Built PPTX approved?
P8 Path C
Review Only (Lightweight Audit)

When to use: Quick audit of existing content, no build planned.

Step 1: Invoke P2 directly ├─ Input: Existing source PPTXs ├─ Decision: If research artifacts missing: │ Option A: Route to P1 auto-preamble (US-6) │ Option B: Proceed with CONTEXT-GAP logged ├─ Produces: REVIEW_REPORT per module (audit findings only) └─ Human Gate: Proceed to build or halt? ├─ Route to P3 → Path B flow └─ HALT → audit report delivered

BUILD_SPEC Derivation (v2.1): BUILD_SPEC is NOT produced by P1. It is derived by the Build team at P3 Phase 0 and P5 Phase 0, just-in-time from IDEAL_BLUEPRINT + RESEARCH_BRIEF (+ REVIEW_REPORT if Mode C). This eliminates re-derivation round-trips after review updates the IDEAL_BLUEPRINT.
