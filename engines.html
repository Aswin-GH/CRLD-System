Layer 02 — Engines

5 engines powering all pipeline operations

Engine Overview

What are Engines?

Engines define the operational logic for research, review, and build processes. Each engine specifies team composition, agent dispatch protocols, scoring/construction rubrics, and I/O contracts. Engines are consumed by Pipelines (Layer 05), which orchestrate them according to user workflows.

12 Categories, 100-point scale: Pedagogical alignment (A), Coherence (B–E), Visual/Digital (F–J), Cognitive progression (K–V). Tier 1 gates (≥70% per category), overall thresholds (Ship-ready ≥85%, Upgradeable 70–84%, Remediate 50–69%, Reframe <50%).

Scoring Framework

9 categories (Aa-Ha naming): Applet-applet scoring with Tier 1/2 gating. Same score bands as Module_Review_Engine. In standalone mode, category Ga (module integration) is excluded and weights redistributed.

Key Design Principles

Three-Team Model (Canonical)

All engines are operated by one of three teams: Research (RA-*), Review (Rev-*), or Build (Bld-*). Each team has 5–8 specialists. Teams are coordinated by Orchestrators (Layer 04_ROLE_AGENTS).

Living Artifacts

IDEAL_BLUEPRINT is a living artifact (Directive 22). Rev-* agents can update their owned sections during review. This eliminates re-derivation round-trips and keeps design documents in sync with review findings.

BUILD_SPEC Derivation (v2.1)

BUILD_SPEC is no longer produced by Chapter_Research_Engine. It is derived just-in-time by Build team at Phase 0 of Module_Build_Engine or Applet_Build_Engine, from IDEAL_BLUEPRINT + RESEARCH_BRIEF (+ REVIEW_REPORT if Mode C).

Section Index Pattern

Research and Review engines include machine-readable Section Index tables. Orchestrators parse these indices to load only required sections, respecting token budget constraints (§0).

Applet Pre-Grounding

Standalone applet pipelines (P5, P6) require 6 pre-grounding inputs because applets are module assets. If any input missing → pipeline halts with MISSING_INPUT status (US-23, US-24).

Completion Thresholds

Each engine specifies completion criteria: {{CONFIG: quality.build_completeness}} (≥95%) or {{CONFIG: quality.build_completeness_with_gap}} (≥85% with gap logged). Thresholds are validated at phase completion gates.
